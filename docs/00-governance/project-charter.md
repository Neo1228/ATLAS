# ATLAS 프로젝트 헌장

## 목적
ATLAS는 여러 판매사(tenant)가 각자 데이터와 권한을 분리해 사용하는 한정판매 환경을 다룬다. 제한된 재고에 요청이 몰릴 때 주문·재고 예약·결제·환불·정산의 정합성과 장애 후 복구를 설계와 실험으로 검증한다. 이 프로젝트는 학습과 재현 가능한 포트폴리오 근거를 위한 것이며, 실제 운영 성과를 주장하지 않는다.

## 장기 범위 — 확정
- **A. 결제 신뢰성 (Payment Reliability):** 결제 승인(authorization)/확정(capture), webhook(웹훅), 환불, 재시도, 중복 방지, 결제 결과가 불확실한 상태와 복구.
- **B. 동시성 높은 한정판매 (Flash Commerce):** 판매사/테넌트, 캠페인, 대기열 입장, 재고 예약, 주문, 동시 요청 처리.
- **C. 정산과 대사 (Settlement & Reconciliation):** 거래 기록 비교, 수수료, 내부 정산 원장, 환불/정정, 감사 추적.
- 세 도메인은 장기 범위에 모두 포함하며 마일스톤별로 순차 진행한다.
- 우선 결제 제공자(PSP)는 PayPal Sandbox다. Fake PSP는 장애를 반복 재현하는 별도 시험 도구이며, 실제 PayPal 장애의 증거가 아니다. 용어는 [Glossary](../01-discovery/glossary.md)를 참조한다.

## 발견 기준 — 확정
문제 탐색은 가상 학습 시나리오로 시작한다. 실제 사용자·문제·인터뷰가 검증됐다고 표현하지 않는다. 여러 판매 유형을 탐색하려는 사용자 선호가 있으며, 공통 구매자/판매자 목표는 D-015~D-017에서 정했다. 대표 유형·순서·유형별 행동·구현 범위는 [Q-002/Q-010](assumptions-and-open-questions.md)에 남아 있다. 첫 기준 가설은 재고/예약 경합과 공정한 구매 기회이며, 정책/인수 기준은 미정 ([D-010](decision-log.md)).

## 초기 제약과 제외 범위 — 확정
- 실결제, 실제 고객 개인정보, 실제 판매사 지급은 초기 실험에서 제외하고 Sandbox 및 가명/합성 데이터를 우선한다.
- 내부 주문 상태와 외부 PSP 결제 상태, 내부 정산 계산과 실제 자금 이동은 각각 분리한다.
- 모듈형 모놀리스 우선은 검증 대상 가설([ADR-0001](../06-decisions/adr/ADR-0001-architecture-style.md))이며 확정 아키텍처가 아니다.
- Gate 0 승인만으로 코드를 시작할 수 없다. Gate 2와 구현 진입을 별도로 승인받은 뒤 시작한다.

## 성공 판단 — 초안
- 정책과 불변조건을 검증 가능한 시나리오 및 테스트/실험과 연결한다.
- 실패·경합·복구의 재현 절차와 한계를 기록한다.
- 성능/복구 주장은 환경과 반복 가능한 실측 근거가 있을 때만 제시한다.
- 수치 목표(SLO, RPS, p95/p99 등)는 미정이며, 사용자 합의와 실험 전까지 가정으로 표시한다. 용어는 [Glossary](../01-discovery/glossary.md)에 정의한다.

## 미결정
페르소나·실제 문제 검증, 상품/판매 단위, 캠페인 공정성, 예약·결제·환불 정책, 정산 의미 및 수수료, 지역/통화/세금/규제, 개인정보 정책, 성능 목표, 기술 버전과 배포 위치는 [Assumptions & Open Questions](assumptions-and-open-questions.md)에서 관리한다.
