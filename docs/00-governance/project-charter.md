# ATLAS 프로젝트 헌장

## 목적
멀티테넌트 한정판매 환경에서 높은 동시 요청을 다루며 주문·재고·결제·환불·정산의 정합성과 장애 복구를 구현·실험으로 검증한다. 학습, 설계 트레이드오프 검증, 재현 가능한 포트폴리오 근거가 목적이며 공모전 참가나 실제 운영 성과가 목적이라고 가정하지 않는다.

## 장기 범위 — 확정
- **A. Payment Reliability:** 승인/캡처, 웹훅, 환불, 재시도, 멱등성, 결제 불확실 상태와 복구.
- **B. Flash Commerce:** 판매사/테넌트, 캠페인, 입장 제어, 재고 예약, 주문, 높은 동시성.
- **C. Settlement & Reconciliation:** 거래 대사, 수수료, 내부 정산 원장, 환불/정정, 감사 추적.
- 세 도메인은 장기 범위에 모두 포함하며 마일스톤별로 순차 진행한다.
- PayPal Sandbox가 우선 연동 대상이다. Fake PSP는 실패 재현용 별도 구현이며 PayPal에서 임의 장애를 강제한다는 뜻이 아니다.
## 발견 기준 — 확정
문제 탐색은 가상 학습 시나리오로 시작한다. 실제 사용자·문제·인터뷰가 검증됐다고 표현하지 않는다. 여러 판매 유형을 탐색하는 것이 사용자 선호이나, 대표 유형·순서·구현 범위는 [Q-002/Q-010](assumptions-and-open-questions.md)에서 구체화한다. 첫 기준 가설은 재고/예약 경합과 공정한 구매 기회이며, 정책/인수 기준은 미정 ([D-010](decision-log.md)).

## 초기 제약과 제외 범위 — 확정
- 실결제, 실제 고객 개인정보, 실제 판매사 지급은 초기 실험에서 제외하고 Sandbox 및 가명/합성 데이터를 우선한다.
- 내부 주문 상태와 외부 PSP 결제 상태, 내부 정산 계산과 실제 자금 이동은 각각 분리한다.
- 모듈형 모놀리스 우선은 검증 대상 가설([ADR-0001](../06-decisions/adr/ADR-0001-architecture-style.md))이며 확정 아키텍처가 아니다.
- 코드 작성은 Gate 0 승인만으로 허가되지 않는다. Gate 2 및 구현 진입의 별도 승인을 받은 뒤 시작한다.

## 성공 판단 — 초안
- 정책과 불변조건을 검증 가능한 시나리오 및 테스트/실험과 연결한다.
- 실패·경합·복구의 재현 절차와 한계를 기록한다.
- 성능/복구 주장은 환경과 반복 가능한 실측 근거가 있을 때만 제시한다.
- 구체적인 수치 목표(SLO, RPS, p95 등)는 미결정이며 측정 전에는 가정으로만 기록한다.

## 미결정
페르소나·실제 문제 검증, 상품/판매 단위, 캠페인 공정성, 예약·결제·환불 정책, 정산 의미 및 수수료, 지역/통화/세금/규제, 개인정보 정책, 성능 목표, 기술 버전과 배포 위치는 [Assumptions & Open Questions](assumptions-and-open-questions.md)에서 관리한다.
