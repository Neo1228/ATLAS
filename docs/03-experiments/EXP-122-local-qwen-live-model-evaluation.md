# EXP-122: 쇼핑 비서와 반품 LLM 검토 층을 로컬 Qwen(Ollama) 실제 모델로 돌려 정책 밖 실행, 금액 불일치, 형식 오류를 센다

- 상태: ✓ 완료(사전 등록 뒤 실행). 결정은 [ADR-0114](../02-decisions/adr/ADR-0114-live-model-findings-tool-loop-and-review-switch.md)와 D-194.
- 날짜: 2026-11-29
- 관련: [#752](https://github.com/Neo1228/ATLAS/issues/752), [ADR-0109](../02-decisions/adr/ADR-0109-shopping-assistant-and-ctype-independent-search.md), [ADR-0110](../02-decisions/adr/ADR-0110-seller-return-refund-recommendation.md), [EXP-120](EXP-120-shopping-assistant-search-and-tool-safety.md), [EXP-121](EXP-121-seller-return-refund-recommendation.md)

## 문제 한 문장

쇼핑 비서와 반품 검토 층은 정해 둔 응답만 돌려주는 가짜 모델로만 검증해서, 실제 모델이 내는 도구 호출 형식, 반복, 응답 언어, 첫 줄 형식에서 무엇이 깨지는지 모른다.

## 사전 등록

실행 전에 쓴 절이다. 실행 뒤에 지표나 판정 기준을 바꾸지 않는다. 바꿔야 하면 "사전 등록과 달라진 점"에 이유와 함께 적는다.

### 조건

- 모델: `qwen2.5:3b`(주), `qwen2.5:1.5b`(비교). Ollama의 OpenAI 호환 endpoint(`/v1`)를 기존 `ATLAS_LLM_*` 설정으로 그대로 쓴다. API key는 주지 않는다. 앱이 보내는 `temperature`는 0이다.
- 앱: Spring Boot 전체 컨텍스트, PostgreSQL 18.6(Testcontainers), PayPal은 기존 시험용 가짜 서버(`PayPalIntegrationTestSupport`). 대화는 `ShoppingAssistantService.converse`로 보낸다(HTTP 컨트롤러는 같은 메서드를 부른다).
- 호스트: Ollama 추론은 CPU·GPU·메모리 대역폭을 차지하므로 생성하는 동안 호스트 측정 잠금(`measure-lock.sh`)을 잡는다. 잠금 없이 잰 지연은 보고하지 않는다.
- 반복: 온도 0이라 칸마다 1회. 같은 입력의 재실행 일치는 3b 쇼핑 과제 3건을 한 번 더 돌려 확인한다.
- 시간 예산: 모델당 쇼핑 집합 40분, 반품 60건 15분. 넘으면 1.5b 쇼핑 집합을 주입 20건으로 줄이고 그 결정을 적는다.

### 집합

1. 주입 20건: EXP-120의 문구를 그대로 쓴다. 앞 10건은 상품 설명에 넣고 구매자는 "상품 좀 봐줘"라고만 말한다. 뒤 10건은 구매자 메시지 자체다. 구매자 지출 상한 50,000원, 사례마다 새 구매자와 새 대화.
2. 쇼핑 과제 17건(한국어 9, 영어 8): 찾기, 담기, 수량 변경·삭제, 합계 확인, 상한 초과 담기, 확인 없는 결제 요청, 확인한 결제 시작, 두 차례 대화. 카탈로그는 실제 판매 상품처럼 이름에 한국어와 영어를 함께 쓴 10개다. 과제마다 새 구매자이고 사전 상태(장바구니, 상한)는 서비스로 직접 넣는다.
3. 반품 권고 라벨 60건(EXP-121, `return-recommendation-cases.txt`): 결정 규칙 결과에 실제 모델 검토를 붙인다.

### 결함 처리 규칙

실제 모델이 드러낸 도구 루프 결함(형식 오류로 차례 실패, 모르는 도구 이름, 끝없는 반복, 요청과 다른 언어, 시스템 프롬프트 규칙 누락)은 기록한 모델 응답을 MockWebServer로 재생하는 시험을 먼저 쓰고(고치기 전 실패), 고친 뒤 통과를 확인한다. 정책 경계를 느슨하게 하는 수정은 하지 않는다.

## 실행 조건

- Ollama 0.40.18, `127.0.0.1`에만 바인드, OpenAI 호환 `/v1`. 앱과 Ollama 사이에 요청·응답을 그대로 적는 로컬 기록 프록시를 두었다(재생 시험의 원응답은 이 기록에서 가져왔다). 앱 설정은 `ATLAS_LLM_ENABLED`·`ATLAS_LLM_BASE_URL`·`ATLAS_LLM_MODEL`·`ATLAS_LLM_READ_TIMEOUT=PT120S`, 키 없음.
- 하네스: `ShoppingAssistantLiveModelEvaluation`(atlas-application, Testcontainers PostgreSQL 18.6, 가짜 PayPal), `ReturnRecommendationLiveReviewEvaluation`(atlas-order). 둘 다 `ATLAS_LLM_LIVE_EVAL=true`일 때만 돈다(CI의 `check`에서는 건너뛴다).
- 모든 생성은 호스트 측정 잠금(`llmeval`)을 잡고 돌렸다. 다른 에이전트의 빌드는 잠금과 무관하게 돌아 load1이 실행마다 달랐다: 기준 3b 14.6~18.8, 기준 1.5b 21.2, 최종 5.9~7.3, 반품 V1·V2 98~127(이 두 실행의 지연은 쓰지 않는다). 지연은 맥락용이고 결론은 건수로 낸다.
- "기준"은 main(e2d5217e)의 코드, "최종"은 이 변경(ADR-0114)의 코드다. 온도 0이지만 시스템 프롬프트나 도구 결과가 바뀌면 경로가 바뀌므로 과제 성공 ±1은 모델 쪽 변동으로 본다.

## 고친 결함과 재생 시험

각 시험은 기록한 원응답 본문을 MockWebServer(쇼핑 비서) 또는 정해 둔 모델(반품 검토)로 재생한다. 수정 전 코드(쇼핑 비서 세 파일을 main으로 되돌리고, 검토 층의 스위치·글 없음 검사를 지움)에서 다섯 시험이 모두 실패했고(`8 tests completed, 3 failed`, `6 tests completed, 2 failed`), 수정 뒤 모두 통과했다. 시험마다 지키는 가드가 하나라 이 실행이 가드별 변이 확인을 겸한다.

| 결함(모델) | 수정 | 시험 |
|---|---|---|
| `limit`에 스키마 객체(3b) | 힌트 인자는 형식이 어긋나면 기본값 | `recordedSchemaEchoInOptionalLimitStillSearches` |
| 없는 줄의 `update_cart(0)`가 성공, "줄였습니다" 전달(3b) | `LINE_NOT_IN_CART` 거절 | `recordedUpdateOfAnInventedCartLineIsRefusedAndItsClaimIsNotDelivered` |
| 빈 응답 전달(1.5b) | 서버 문장으로 바꿈 | `recordedEmptyReplyIsNotDeliveredAsAnEmptyString` |
| 글 없는 승인을 사유 코드만 보고 강등(3b) | 글이 없으면 모델을 부르지 않음 | `recordedDowngradeOfAnApprovalWithoutBuyerTextIsNotApplied` |
| 비서용 설정이 검토 층까지 켬 | 검토 층 별도 스위치(기본 꺼짐) | `reviewSwitchOffNeverCallsTheSharedModel` |

## 사전 등록과 달라진 점

- 재실행 일치 확인(3b 과제 3건 재실행): ✗ 수행하지 않았다. 대신 3b 전체 집합을 코드가 다른 네 구성으로 돌렸고, 결론은 구성 간 차이가 아니라 0이어야 하는 지표(정책 밖 실행, 전달 금액 불일치, 승인 쪽 이동)로 냈다.
- 시도하고 기각한 변경을 같은 하네스로 쟀다: 시스템 프롬프트 규칙 추가, 언어 불일치 응답의 문맥 재작성과 문맥 없는 번역, 검토 층 프롬프트 V1·V2, 첫 줄 관대한 해석. 측정값과 기각 이유는 ADR-0114 "대안과 기각 이유"에 있다. 번역 단계는 3b 마지막 번역 10건 중 6건이 응답에 인용된 판매자 설명의 주입 문구를 따랐다.

## 한계

- 모델 두 개, 모두 소형(3B·1.5B)이다. 상용 모델의 품질은 이 결과로 말할 수 없다. 하네스는 `ATLAS_LLM_*`만 바꾸면 같은 집합을 돈다.
- 쇼핑 과제 17건과 카탈로그 10개는 작성자가 만들었다. 과제 성공률은 이 집합의 값이다.
- 반품 검토 프롬프트 비교는 평가와 같은 60건으로 했다(별도 검증 집합 없음).
- 원자료(차례별 기록, 프록시 기록)는 저장소에 올리지 않았다. 숫자의 정본은 이 표다.
