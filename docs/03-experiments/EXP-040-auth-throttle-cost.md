# EXP-040: 인증 시도 제한의 비용

**추적 이슈:** [#413](https://github.com/Neo1228/ATLAS/issues/413)

**상태:** 실측 완료 · PostgreSQL 18.6 컨테이너, 로컬 단일 호스트

## 왜 이 실험을 했는가

PR #414에서 인증 경로에 DB 기반 시도 제한을 넣으면서, ADR-0048에 "PBKDF2 수십 ms에 비하면 무시할 수준"이라고 적었습니다. 그런데 이 문장은 **측정하지 않은 추정**이었습니다. 같은 ADR이 "측정 없이 성능을 주장하지 않는다"를 근거로 외부 인프라를 배제한 결정을 담고 있으므로, 자기 모순이었습니다.

답해야 할 질문은 두 개입니다.

1. 카운터 SQL은 서버에서 얼마나 비싼가?
2. 앱이 실제로 쓰는 **2 transaction + round-trip** 비용은 얼마이며, PBKDF2 검증 비용과 비교해 무시할 수 있는가?

## 방법

- 실제 `V49` 스키마와 같은 두 테이블(`auth_subject_bucket`, `auth_origin_bucket`)을 별도 DB에 생성
- 프로덕션 SQL을 그대로 사용: `isOverSubjectLimit` 조회 + `consumeOrigin` upsert + `recordSubjectFailure` upsert
- **측정 A (서버 내부 비용)**: `DO` 블록으로 2000회 반복, 3라운드. 네트워크·commit 제외
- **측정 B (앱 경로 근사)**: `BEGIN … COMMIT` 쌍 2개(= `REQUIRES_NEW` 2회)를 200회 실행, 3라운드. 같은 호스트에서 클라이언트 실행
- 매 라운드 테이블 `TRUNCATE` 후 시작
- 내구성 설정 명시: `synchronous_commit=on`, `fsync=on`
- 비교 기준: 같은 구성의 `DelegatingPasswordEncoder("pbkdf2")`로 `matches` 1회를 10회씩 5라운드

## 결과

### PBKDF2 검증 비용 (비교 기준)

| 라운드 | ms/verify |
| ---: | ---: |
| 1 | 58.3 |
| 2 | 50.3 |
| 3 | 52.7 |
| 4 | 47.7 |
| 5 | 47.9 |

**범위 47.7–58.3 ms, 중위 50.3 ms.** `login`은 존재 여부를 감추기 위해 이를 두 번 수행합니다.

### A. 카운터 SQL 서버 내부 비용

| 라운드 | ms/시도 (3 statement) |
| ---: | ---: |
| 1 | 0.0452 |
| 2 | 0.0451 |
| 3 | 0.0453 |

### B. 앱 경로 근사 (2 transaction + round-trip)

| 라운드 | ms/시도 |
| ---: | ---: |
| 1 | 0.738 |
| 2 | 0.711 |
| 3 | 0.712 |

**범위 0.711–0.738 ms, 중위 0.712 ms.**

### 비교

| 항목 | 값 |
| --- | ---: |
| PBKDF2 검증 1회 (중위) | 50.3 ms |
| 카운터 앱 경로 1회 (중위) | 0.712 ms |
| 비율 | **약 1.4 %** |

즉 한도 확인을 비밀번호 검증 **앞**에 두면, 검증 1회 값을 치르기 전에 0.7 ms로 거절할 수 있습니다.

## 해석과 한계

- 서버 내부 비용(0.045 ms)과 앱 경로(0.712 ms)의 차이는 대부분 **transaction 경계와 round-trip**입니다. SQL 튜닝으로 줄일 수 있는 부분이 거의 없다는 뜻입니다.
- 절대값은 로컬 단일 호스트 결과입니다. 운영에서는 네트워크 RTT와 풀 경쟁이 더해집니다.
- 풀이 포화되면 이 0.7 ms도 커집니다. 그 상태는 `atlas.datasource.pool-budget-per-replica`와 인증 경로 대기가 함께 관측되어야 하며, 카운터만의 문제로 보면 안 됩니다.
- 이 실험은 **비용**만 측정했습니다. 공격 트래픽 차단 효과(거절률, CPU 절감)는 별도 측정 대상입니다.

## 결정에 미친 영향

- ADR-0048의 "무시할 수준"이라는 추정을 위 측정값으로 대체했습니다.
- 카운터 커넥션 예산을 별도 풀로 분리하는 것은 **보류**합니다. 현재 비용이 검증 비용의 1.4 %이고, 풀 포화는 카운터 고유 문제가 아니므로, 분리 전에 풀 예산 지표로 실제 포화를 먼저 관측해야 합니다.
